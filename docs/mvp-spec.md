Основа: разбор Honeydew (22 скриншота + 10 записей экрана, 01.10 и 03.10.2026) и продуктовые принципы проекта.

**Что нового в v0.2 (03.10.2026):** поиск в три уровня (§1, §3), уточнён разбор поиска и чата (§2), черновики рецептов и рецепт-как-ингредиент (§6), каталог приложения перенесён в MVP, этапы перестроены (§8), подробные флоу второго этапа — в `stage-2-flows.md`.

## 1. Идея и принципы
TableTop — личная кулинарная книга со встроенным ИИ-агентом: сохраняет рецепты откуда угодно (соцсети, сайты, фото), организует их, строит план меню и список покупок.

1. **Fast-first** — 1000 рецептов листаются так же плавно, как 50. UI никогда не ждёт ИИ.
2. **Save anything** — ссылка, видео, скриншот, фото, текст, вручную.
3. **Visual-first** — карточки с фото.
4. **Честный ИИ** — видно, что взято из источника, а что дописал ИИ. Автор и ссылка на оригинал сохраняются.
5. **ИИ работает поверх твоей базы** — агент видит библиотеку, план и список через инструменты.
6. **Сначала дёшево, потом ИИ** — поиск идёт по уровням: у себя → каталог приложения → интернет. Токены тратятся только там, где без ИИ не обойтись.
7. **Импорт — чтобы собрать своё, поиск — чтобы найти новое.** Импорт сводит в одно место рецепты из соцсетей и книг. А новый рецепт должно быть удобнее искать в TableTop, чем в Google или TikTok.

## 3. Границы MVP
**Входит:**
1. Регистрация/логин (email + пароль, JWT).
2. Библиотека: сетка/список, поиск (по части слова, с опечатками, по названию/тегам/ингредиентам), папки, избранное, теги.
3. Рецепт: создание вручную, просмотр, редактирование, удаление, фото, Scale порций, источник и автор.
4. Импорт: по ссылке на сайт, по ссылке на YouTube, по скриншоту/фото рецепта — асинхронно, со статусом.
5. Замена ингредиента через ИИ (с кешем).
6. Список покупок: из рецепта и вручную, группировка, отметки, объединение одинаковых.
7. План меню на неделю + «весь план в список покупок».
8. Поиск в три уровня: **у себя** → **каталог приложения** (курируемые классические рецепты, без ИИ) → **онлайн** (обычный поисковый API, ИИ только для разбора выбранной страницы через импорт). Онлайн — только если выше пусто или по кнопке.

**Не входит (v2):** чат-агент, AI Edit, КБЖУ, TikTok/Instagram, фото блюда, ачивки, семья, Discover и публикация своих рецептов, таймеры, рецепт-как-ингредиент (только поле в схеме).

**Требования к будущему агенту (v2), чтобы не повторить ошибки Honeydew:** отвечает на языке пользователя; найденный рецепт сразу становится черновиком в диалоге, и правки («сделай тонкое тесто») меняют черновик, а не запускают поиск заново; диалоги хранятся в БД и не пропадают при смене вкладки; в модель уходит резюме + последние N сообщений; поиск идёт по уровням, интернет — последним.

## 4. Нефункциональные требования
- Список из 1000 рецептов: ответ API < 200 мс на страницу, плавный скролл.
- Экран рецепта открывается без вызова ИИ.
- Любая ИИ-операция: асинхронно или со спиннером ≤ 15 с, таймаут, кнопка отмены, понятная ошибка.
- Задача импорта переживает перезапуск приложения и сервера.
- Покрытие доменной логики (масштабирование, объединение ингредиентов) unit-тестами.
- Поиск у себя и по каталогу — без вызова ИИ, < 200 мс на 1000 рецептов.

## 5. Предлагаемый стек
- **Backend:** Java 21, Spring Boot 3 (Web, Data JPA, Security, Validation), PostgreSQL, Flyway, Maven, JUnit 5 + Testcontainers.
- **Импорт/ИИ:** Jsoup (schema.org/Recipe), YouTube Data API (описание) + субтитры, LLM API со structured output (JSON-схема рецепта).
- **Хранение фото:** AWS S3 на проде, локально — папка на диске за интерфейсом `ImageStorage`, в тестах LocalStack.
- **Frontend:** React + TypeScript (PWA, mobile-first) — быстрее старт, чем нативное приложение; позже можно React Native.
- **Деплой:** Docker Compose локально; затем AWS (ECS/App Runner или Lambda + RDS).

## 6. Модель данных (черновик)
- `users` (id, email, password_hash, settings jsonb)
- `recipes` (id, user_id **nullable — NULL у рецептов каталога**, title, description, servings, total_time_min, source_url, source_author, source_type [manual/web/youtube/image/catalog], catalog_recipe_id nullable (если скопирован из каталога), language, cover_image_url, notes, is_favorite, ai_generated_fields jsonb, created_at, updated_at, deleted_at nullable)
- `recipe_ingredients` (id, recipe_id, position, raw_text, name, quantity numeric nullable, unit nullable, note, category, **linked_recipe_id nullable** — для рецепта-как-ингредиента, v2)
- `recipe_steps` (id, recipe_id, position, text, ai_generated bool)
- `tags`, `recipe_tags`
- `folders` (id, user_id, name), `folder_recipes`
- `favorites` — флаг в recipes или отдельная таблица
- `import_jobs` (id, user_id, type, input, status [PENDING/PROCESSING/DONE/FAILED], recipe_id, error, created_at, updated_at)
- `recipe_drafts` (id, user_id, origin [import/agent/web_search], payload jsonb, status [PENDING/SAVED/SKIPPED], recipe_id nullable, created_at) — найденный, но ещё не сохранённый рецепт
- v2: `chat_sessions` (id, user_id, title, summary, created_at), `chat_messages` (id, session_id, role, content, draft_id nullable, created_at)
- `grocery_items` (id, user_id, name, quantity, unit, category, checked, recipe_id nullable)
- `meal_plan_entries` (id, user_id, date, meal_type nullable, recipe_id nullable, custom_text)
- `ingredient_substitutions_cache` (ingredient_key, response jsonb, created_at)

- `POST /auth/register`, `POST /auth/login`
- `GET /recipes?query=&tag=&folderId=&favorite=&sort=&cursor=&limit=` · `GET/PUT/DELETE /recipes/{id}` · `POST /recipes` · `POST /recipes/{id}/restore` · `PATCH /recipes/{id}/favorite`
- `POST /images` → `{imageId, url}`
- `GET /catalog?query=&cursor=` · `GET /catalog/{id}` · `POST /catalog/{id}/copy`
- `GET /search/web?query=` → список ссылок · далее `POST /imports` по выбранной
- `POST /imports` {type, url | imageId} → `{jobId}` · `GET /imports/{id}` · `GET /imports?status=active`
- `GET /ingredients/{name}/substitutions`
- `GET/POST /folders`, `POST /folders/{id}/recipes`
- `GET /grocery` · `POST /grocery/items` · `POST /grocery/from-recipe/{id}` {ingredientIds} · `PATCH /grocery/items/{id}`
- `GET /plan?from=&to=` · `POST /plan` · `DELETE /plan/{id}` · `POST /plan/to-grocery?from=&to=`

## 9. Решения (02.10.2026)
- Соло-проект, Даник — консультант.
- Интерфейс: английский по умолчанию + переключение языка (i18n). В отличие от Honeydew, **переводится и контент рецепта**: «Показать на моём языке» — перевод через Gemini, кешируется в `recipe_translations`, оригинал всегда доступен.
- Единицы в списке покупок — «магазинные»: г, кг, мл, л, шт., пачка, упаковка, пакет, бутылка, банка, ящик. Кухонные (чашка, ч. л., ст. л.) — только в рецептах; при переносе в список конвертируются (200 ml молока → 1 бутылка/200 мл, 1 tsp соли → «соль», без количества). lb/oz — только в imperial-режиме.
- ИИ: Gemini API (Flash) через абстракцию `LlmClient`, чтобы провайдера можно было сменить.
- Платформа: адаптивное веб-приложение (PWA) — mobile-first, устанавливается на экран телефона, работает и на десктопе.

- (03.10.2026) Поиск в три уровня: у себя → каталог → онлайн. Каталог (только курируемый) — в MVP.
- (05.10.2026) TikTok/Instagram: в MVP только подпись и обложка (если рецепт в описании — разбираем, если нет — просим скриншот или текст). Разбор самого видео (кадры, жесты) — v2, через загрузку файла пользователем: официального способа скачать чужое видео нет. Honeydew это умеет: рецепт сохранился из видео без подписи и внятного голоса.
- (05.10.2026) Кнопка «Поделиться» на iPhone: PWA туда не попадает (Web Share Target не поддерживается в iOS ни в Safari, ни в Chrome — оба на WebKit). В MVP — вставка ссылки + автоподхват из буфера; позже — быстрая команда iOS (Shortcuts) или нативное приложение.
- (03.10.2026) Название рецепта после правок ИИ: при сохранении предлагать новое название, пользователь подтверждает или правит.
