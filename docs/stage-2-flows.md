# TableTop — Этап 2: рецепты и библиотека. Флоу

Версия 03.10.2026. Дополняет `mvp-spec.md` (v0.2).

Цель этапа: пользователь может вручную создать рецепт, найти его, открыть, пересчитать порции, отредактировать, удалить и разложить по папкам. Без ИИ.

## Решения этапа

| Вопрос | Решение | Почему |
|---|---|---|
| Поиск | По названию, тегам и ингредиентам; по части слова и с допуском опечаток через `pg_trgm` | Honeydew не находит «peperoni» при опечатке. Для «у себя» ИИ не нужен |
| Ингредиенты | Хранить `raw_text` (как ввёл пользователь) + разобранные `quantity`, `unit`, `name` | Нужно для Scale и для будущего списка покупок. Если строку не разобрать, рецепт всё равно сохраняется |
| Фото | Интерфейс `ImageStorage`: локально файлы на диске, на проде AWS S3; в тестах S3 эмулирует LocalStack (Testcontainers). В рецепте хранится id картинки | Код не зависит от хранилища. MinIO не берём: в 2026 году его бесплатная версия заброшена, Docker-образы удалены |
| Удаление | Мягкое: `deleted_at`, кнопка «Отменить» в тосте, корзина 30 дней | Случайное удаление рецепта болезненно |
| Пагинация | Keyset (курсор по `updated_at, id`) | Стабильно быстро на 1000+ рецептов |
| Порции | Пересчёт на клиенте, в базе хранится оригинал | Мгновенно, не портит данные |
| Чужие данные | Любой запрос к чужому рецепту → 404 | Не раскрываем, что такой id существует |

## Флоу 1. Создание рецепта вручную

**Шаги пользователя**
1. На главной нажимает «+» → «Вручную».
2. Заполняет форму:
   - название (обязательно);
   - фото (необязательно);
   - порции, время, источник (ссылка или «бабушкина тетрадь»), автор;
   - ингредиенты: по одной строке, «200 г муки». Можно вставить сразу список, и он разобьётся по строкам;
   - шаги: по одному, порядок меняется перетаскиванием;
   - теги (автодополнение из своих тегов), заметки.
3. Нажимает «Сохранить» → открывается экран рецепта.

**Что улучшаем по сравнению с Honeydew**
- Количество вводится обычной системной клавиатурой в той же строке, а не своей цифровой.
- Нет «unit» по умолчанию: если единицу не указали, её просто нет.
- Строка «2 яйца» разбирается сама: количество 2, единица «шт.», название «яйца». Разбор показывается подсказкой, его можно поправить.

**Бэкенд**
- `POST /api/images` (multipart) → `{imageId, url}`. До 10 МБ, только jpeg/png/webp/heic.
- `POST /api/recipes` с JSON → 201 и созданный рецепт.
- Разбор строки ингредиента — сервис `IngredientParser`, чистая доменная логика, покрыта unit-тестами.
- Валидация: название 1–200 символов, порции 1–100, время 0–2880 минут, до 100 ингредиентов и 100 шагов.

**Ошибки**
- Нет названия → 400, поле `title` подсвечено.
- Фото слишком большое или не того формата → 400 до сохранения рецепта, остальные поля не теряются.
- Пропал интернет при сохранении → форма остаётся заполненной, кнопка «Повторить». Черновик формы хранится локально в браузере.

## Флоу 2. Просмотр рецепта и Scale порций

**Шаги**
1. Открывает рецепт из библиотеки.
2. Видит фото, название, время, порции, источник (ссылка кликабельна), теги, ингредиенты с чекбоксами, шаги, заметки.
3. Меняет порции «–»/«+» или вводит число → количества пересчитываются сразу.
4. Отмечает чекбоксами, что уже положил. Отметки живут до закрытия рецепта.

**Правила пересчёта**
- Умножаем только `quantity`. Если его нет («соль по вкусу»), строка не меняется.
- Округление по-человечески: 1.333 → 1⅓, 0.25 ч. л. → ¼ ч. л., яйца → целые, с пометкой «≈», если округлили.
- Кнопка «Сбросить» возвращает исходные порции.

**Бэкенд**
- `GET /api/recipes/{id}` → полный рецепт. ИИ не вызывается.
- Логика пересчёта и округления — отдельный класс `ServingsScaler` с unit-тестами (она же понадобится для списка покупок). На фронте её же повторяем на TypeScript или отдаём `?servings=` с бэкенда — решим при реализации.

## Флоу 3. Редактирование

**Шаги**
1. На экране рецепта «⋯» → «Редактировать».
2. Открывается та же форма, что при создании, с заполненными полями.
3. «Сохранить» → экран рецепта с изменениями. «Отмена» с несохранёнными изменениями → вопрос «Выйти без сохранения?».

**Бэкенд**
- `PUT /api/recipes/{id}` — рецепт целиком, ингредиенты и шаги заменяются списком.
- Защита от одновременной правки с двух устройств: поле `version` (`@Version` в JPA). Если версия устарела → 409 «Рецепт изменился на другом устройстве, обновите страницу».

## Флоу 4. Удаление

**Шаги**
1. «⋯» → «Удалить» → подтверждение «Удалить рецепт „…“?».
2. Возврат в библиотеку, тост «Рецепт удалён · Отменить» на 5 секунд.
3. Удалённые рецепты 30 дней лежат в «Недавно удалённых» (профиль), оттуда можно восстановить.

**Бэкенд**
- `DELETE /api/recipes/{id}` → 204, ставит `deleted_at`.
- `POST /api/recipes/{id}/restore` → 200.
- Все запросы библиотеки и поиска фильтруют `deleted_at IS NULL`.
- Ночная задача (`@Scheduled`) удаляет насовсем то, что старше 30 дней, вместе с фото.

## Флоу 5. Библиотека и поиск у себя

**Главный экран**
1. Сверху поиск, под ним чипы фильтров: «Избранное», теги.
2. Переключатель «Сетка / Список», выбор запоминается в `users.settings`.
3. Сортировка: недавно добавленные (по умолчанию), по названию, по времени готовки.
4. При прокрутке подгружаются следующие 30 рецептов. Картинки — маленькие превью, грузятся по мере появления на экране.
5. Пустая библиотека → экран «Здесь будут ваши рецепты» и кнопки «Создать», «Импортировать» (импорт появится в этапе 4).

**Поиск**
1. Ищет по мере ввода, с задержкой 250 мс, начиная с 2 символов.
2. Совпадения: название, теги, ингредиенты. «Lasa» → лазанья, «peperoni» → пицца с пепперони, «фарш» → лазанья (по ингредиенту).
3. В выдаче сначала совпадения в названии, потом в тегах, потом в ингредиентах. Совпавший кусок подсвечен.
4. Если ничего не нашлось → «У вас нет рецептов по запросу „…“» и две кнопки: «Искать в каталоге TableTop» (этап 3) и «Искать онлайн» (этап 4). До этих этапов кнопки скрыты.

**Бэкенд**
- `GET /api/recipes?query=&tag=&folderId=&favorite=&sort=&cursor=&limit=30` → `{items, nextCursor}`. В элементах только то, что нужно для карточки: id, название, превью, время, порции, теги.
- Миграция: `CREATE EXTENSION pg_trgm`, GIN-индексы `gin_trgm_ops` на `lower(title)`, на именах тегов и на `recipe_ingredients.name`.
- Запрос: `similarity` / оператор `%` для опечаток плюс `ILIKE '%…%'` для части слова; ранжирование по месту совпадения.
- Тест производительности: 1000 рецептов в Testcontainers, поиск и страница < 200 мс.

## Флоу 6. Папки и избранное

**Шаги**
1. На главной раздел «Папки»: список папок с количеством рецептов и обложкой первого.
2. «Новая папка» → название → создана.
3. Добавить рецепт в папки: на экране рецепта «⋯» → «В папку» → список папок с галочками (рецепт может быть в нескольких).
4. Открыть папку → та же библиотека, отфильтрованная по папке, с тем же поиском.
5. Переименовать или удалить папку. При удалении папки рецепты остаются в библиотеке.
6. Избранное — сердечко на карточке и на экране рецепта, фильтр «Избранное» на главной.

**Бэкенд**
- `GET/POST /api/folders`, `PATCH/DELETE /api/folders/{id}`.
- `PUT /api/recipes/{id}/folders` с `{folderIds: [...]}` — сразу весь набор папок рецепта.
- `PATCH /api/recipes/{id}/favorite` `{favorite: true}`.
- Название папки уникально у пользователя без учёта регистра → иначе 409.

## Модель данных этапа (миграция V2)

```
recipes            id, user_id, title, description, servings, total_time_min,
                   source_url, source_author, source_type, catalog_recipe_id,
                   language, cover_image_id, notes, is_favorite,
                   version, created_at, updated_at, deleted_at
recipe_ingredients id, recipe_id, position, raw_text, name, quantity, unit,
                   note, category, linked_recipe_id (v2, пока всегда NULL)
recipe_steps       id, recipe_id, position, text, ai_generated
tags               id, user_id, name           (unique: user_id + lower(name))
recipe_tags        recipe_id, tag_id
folders            id, user_id, name, created_at
folder_recipes     folder_id, recipe_id, added_at
images             id, user_id, storage_key, content_type, size_bytes, created_at
```

`user_id` у `recipes` сразу делаем nullable под каталог этапа 3, но в этапе 2 он всегда заполнен.

## Что изучите на этом этапе
- Связи в JPA: `@OneToMany`, `@ManyToMany`, каскады и `orphanRemoval`; проблема N+1 и как её видеть в логах.
- Оптимистичная блокировка (`@Version`).
- Индексы и `EXPLAIN ANALYZE` в PostgreSQL, расширение `pg_trgm`.
- Курсорная пагинация.
- Загрузка файлов (multipart), паттерн «интерфейс + несколько реализаций», AWS S3 и LocalStack.
- Первый фронтенд на React + TypeScript: роутинг, формы, бесконечная прокрутка.
